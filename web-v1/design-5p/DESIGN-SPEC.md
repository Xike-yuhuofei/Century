# Century UI/UX V1.0 · 五人模式与核校卡表统一

**任务范围：** 原高保真 UI 演示改为 2 名真人 + 最多 3 名 AI（0～3 自选，默认 3），不扩展六人规则。第一优先是以仓库根目录 `data/cards.json` 统一卡牌效果、编号和数值。Windows 桌面 Chrome / Edge，3440 × 1440。

## 1. 唯一卡牌数据源与核对依据

- GitHub 主仓库：`https://github.com/Xike-yuhuofei/Century`。
- 唯一权威项目数据：`main/data/cards.json`（核校日期 2026-10-19），与 `02-卡牌总表.md` 对应。
- 本地快照：`reference/cards-canonical.json`，由核校卡牌数值重建，**字段数值逐项匹配**根目录，可能不与 GitHub 文件按字节完全相同。
- 全集：2 种起始卡，每种 5 份；43 张独立商人卡（创造 8、升级 1、交易 34）；36 张魔像卡。合计 89 张实体卡。
- 用固定顺序把起始卡、商人卡和魔像的 **ID／类型／输入／输出／升级次数／分值／理论参考字段**序列化，与实时从根目录读取的内容分别计算 FNV-1a 数据指纹，两者一致：`2fd96cfc`（序列化长度 2534）。**指纹用于一致性检查，不是信息安全校验。**
- 核心例子：M29 为黄×4 → 蓝×2；M43 为升级 3 次；S01（创造黄×2）与 S02（升级 2 次）各 5 份。
- 所有卡牌按水晶实际颗数绘制，不使用「数量 ×n」替代。

**旧 V1 分支必须修复：** `web-v1/src/data.ts` 将 M01–M08 错置为创造、M09 错置为升级；旧版的 `S1C/S1U` 等不是根目录的卡面编号。交付中 `repo-migration/` 提供本地生成器与迁移补丁，**没有向 GitHub 推送任何内容**。必须隔离旧版编号的浏览器存档，不能照旧复用历史商人 ID 状态。

## 2. 布局：比较并选定 A

可视宽度分配：浏览器内容宽 3440px；外侧 22px×2；栏距 12px×2；三栏内容总宽 3372px。

| 方案 | 左真人 | 中央共享桌面 | 右真人 | 结论 |
|---|---:|---:|---:|---|
| A：双翼固定 | 约 1047px | 约 1278px | 约 1047px | **采用**：12–16 张可用商人卡仍有相对完整的手牌区域 |
| B：中央优先 | 900px | 1572px | 900px | 备选：市场更宽，但真人手牌更易拥挤 |

AI 信息固定占中央顶部：默认 3 张并排摘要卡；数量为 0 时隐藏，1–2 时自动等分中央宽度，**不会改变真人栏宽**。每张摘要仅显示身份、得分、当前水晶、商人卡数量、已认领魔像数量、回合状态。魔像行始终 5 张，商人市场始终 6 张。

## 3. 核心组件规范

| 组件 | 设计尺寸／行为 |
|---|---|
| 顶栏 | 高 68px；显示人数配置、轮次、密度、真人演示切换 |
| 左右玩家区域 | 高约 1344px；彼此对称，始终常驻 |
| 卡牌网格 | 标准 5 列；紧凑 6 列；各容器可局部滚动，整页不滚动 |
| 商人卡 | 标准高度 128px，折叠演示已打出高度 112px；水晶逐颗显示，类型有底色差异 |
| 魔像卡市场 | 5 列，可认领高亮，展示实际需求、分值、硬币与缺口 |
| 商人市场 | 6 列，展示输入/输出水晶、卡位成本和已有附赠水晶 |
| AI 摘要 | 0–3 份，中央顶部高度约 106px；可按数量自适应 |
| 操作台 | 与市场同时可见，预览交易倍数、升级路径、获取支付、魔像认领与超容量弃置 |
| 排列方式 | 玩家独立拖拽、类型排序、右键固定；悬停放大；回收区折叠 |
| 商队容量 | 上限 10 颗；**在回合结束时**处理超额，而不是取得水晶瞬间 |
| 窗口自适应 | 3440×1440 基准，验证 3000×1200、2600×1200、2000×1080 |

**视觉 Token：** `--bg:#080F17`，`--panel:#101B27`，`--panel2:#152230`，`--text:#E9EEED`，`--gold:#E7C88E`；水晶以黄、绿、蓝、粉四色为首要识别。绝大多数正文 11–13px；正式产品建议在 100% 缩放下将极小标签抬至 11px 以上。

## 4. 五人规则约束

- 2 名人类 + 0～3 名 AI，总玩家数 2～5；**满员五人局无需虚构第六套起始卡**。
- 五人局起始卡：每位玩家 1 张 S01、1 张 S02，正好各使用 5 份；五个起始库存遵循已有 `01-规则精读.md`。
- 五人局铜币与银币初始分别 10 枚；**每人认领第 5 张魔像触发终局**，并完成当前完整轮。
- 每回合四选一：打出、获取、休息、认领。交易可在资源允许时重复执行；升级可连续作用于同一颗水晶；市场获取向目标左侧每卡压 1 颗水晶。
- 原型中 **8 枚铜币和 6 枚银币属于已认领卡后剩余数量**，与示例各玩家已获得的币数相加后均为 10。演示状态不是由完整真实五人牌局逐回合重演生成。

## 5. 交互测试（2026-10-19）

使用 Playwright + Chromium 对独立 HTML 测试：

- **27 / 27 项检查通过**，涵盖两真人常驻、0～3 AI 适配、5 张魔像、6 张商人、起始卡编号、核校卡表效果、硬币数量、水晶逐颗绘制、卡牌拖拽、交易预览、已打出折叠与容量弃置。
- 30 次连续**真人操作演示**：打出 19、休息 8、认领 3；测试样本中模拟溢出 13 次；合计 78 次点击，平均 2.6 次每动作（含弃置）。仅用于发现交互/布局故障，不能等同于五人规则引擎验证。
- 4 种测试视口（3440×1440、3000×1200、2600×1200、2000×1080）整页均无横向/纵向溢出；脚本错误为 0。
- 测试记录见 `qa-results.json`，主图为 `century-3440x1440-5p.png`。

## 6. 尚待接入的正式功能

本次为**五人布局交互原型 + 已核校卡牌数据 + 本地 V1 数据迁移工具**。AI 摘要为静态示例，连续操作演示只在两名真人之间切换，不代表引擎真实走过 AI 回合。已展示交易/升级/获取/认领预览，但尚未完整接入真实 `engine.ts` 的五人状态机、AI 自动行动、牌堆洗切、终局完整轮、重连或持久化。

### 正式开发次序

1. 在本地 V1 分支执行 `repo-migration/README.md` 说明的卡牌生成和旧存档隔离；重新运行规则测试并更新涉及旧 ID 的断言。
2. 将真实游戏的 `2 真人 + 0～3 AI` 路由到固定双翼布局，不得退回现有的通用多人布局。
3. 将 UI 的操作台转换为由规则引擎验证的动作草稿，不允许直接在 UI 修改比分/库存作为游戏真值。
4. 将 AI 玩家按真实座次加入每轮顺序，五人测试按 5 张魔像触发终局。
5. 在实机上用每边 20–30 张牌的大手牌、含回合溢出/重复交易/持续竞争的场景做 30 回合多人可用性复测。
