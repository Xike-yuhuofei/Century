### 1.2 发现的架构问题

1. **信息公平性无强制机制（最重要）**。`chooseAIAction(game)` 接收完整 `Game`，其中 `merchantDeck`/`golemDeck` 是隐藏牌库顺序。当前仅靠注释约定"不读取"，无类型隔离、无运行时隔离、无静态扫描。任何后续改动都可能无意间破坏公平性。
2. **决策参数全部硬编码**。约 40 个魔法数字（`.6`、`2`、`.9`、`.35`、`2.6`、`.90` 等）散落在求值与规划函数中；任务书要求的 8 个可调参数中只有 engine/tempo/contest 以 profile 字段形式存在，其余（synergy、goal、capacity、rest、endgame）无显式参数化，无法集中优化。
3. **无训练基础设施**。仓库中没有自动对战模拟器、参数进化、冠军管理、失败诊断等任何训练组件；`benchmark-ai.mjs` 仅支持 2 人对吵式赛马，不支持 5 人局、座位轮换、版本混战与统计检验。
4. **构建脚本与文件名耦合**。`scripts/build.mjs` 按固定模块名清单内联打包（desktop/standalone/mobile/worker 四条路径），AI 拆分为 `ai/` 目录时若不同步更新会导致 standalone 断链；`ai-v2.yml` 还用字符串 `function choosePlan(game)` 检查独立产物。
5. **main 分支存在预置失败测试**（非本任务引入，见 1.3），属于 AI 决策质量缺陷，需在本项目中按"提升质量"方向修复，而不是放松断言。
6. **AI 内部无随机源**（确定性好，利于复现），但也没有 AI 随机种子注入点；策略差异只来自座位 profile。

### 1.3 预置失败测试诊断

`tests/ai-v2.test.mjs` 第 43 行「V2.0 将休息回合计入认领路线」：场景手牌为空（`M20/M23` 已打出），期望规划目标 `G14`（12 分，费用 4 蓝，可由 M20×2 + M23×2 + rest 路线达成），实际目标 `G04`（20 分，费用含 3 粉，当前牌组根本无法达成）。

根因分析：初始手牌为空时，束搜索第一层的合法动作只有 `rest` 与最多 6 张市场卡 × 3 种支付组合 ≈ 18 个 acquire 变体。`rest` 的即时质量（约 0.17）低于多数 acquire 变体，被宽度 14 的束剪枝淘汰；`G14` 的 solved 路线因此永远无法被发现，`G04` 的高分预期（prospective）胜出。修复方向：保证 `rest` 后继（以及一切可达 solved 路线的分支）不被纯即时质量剪掉——在束中为 `rest` 后继保留席位。

### 1.4 训练系统 V1 部署包

任务书提到"尚未完成正式集成验证的训练系统 V1 部署包"。已在本工作区全量搜索（`*train*`、`*训练*`、`*champion*`），**该部署包在当前环境中不存在**。本项目的训练系统按任务书规格从零建设，不假设任何未验证实现。

## 二、开发计划（按任务书七个阶段）

| 阶段 | 交付物 | 关键设计 |
| --- | --- | --- |
| 二 | `training/simulator/` 五人自动对战模拟器 | 复用正式引擎 `applyAction`；5 席全 AI（人类席位由被测版本代理，仅训练环境）；固定种子；行动/决策耗时统计；死循环与异常 → `anomaly` 状态且不计入胜率；保存完整对局与 Replay |
| 三 | `web-v1/src/ai/` 模块化 + `AIObservation` | `observation.ts` 只复制公开字段并冻结；AI 决策函数仅接受观察；`game.merchantDeck/golemDeck` 在 `src/ai/**` 中零引用（静态扫描测试）；deck 顺序随机化不变性测试 |
| 四 | `training/optimizer/` 参数进化 | 8 个任务参数全部实现为"默认值 = 1.0 的既有求值项乘子"，保证基线行为逐位不变且每个参数真实生效（灵敏度测试验证非虚假参数）；(μ,λ) 进化 + 独立验证种子 |
| 五 | `training/tournament/` 冠军挑战 | 双向混战（候选 1 席 + 冠军 4 席 ↔ 候选 4 席 + 冠军 1 席）× 座位轮换 × 配对种子，合并期望胜率 50%；Wilson 95% 置信区间下界 > 50% 才晋级，不确定则保留冠军 |
| 六 | `.github/workflows/ai-training.yml` | PR 快速评估 / 每日参数优化 / 每周冠军挑战 / 手动触发（局数、种子、时间预算）；时间预算守卫；断点状态文件；产物上传；仅晋级任务具备最小写权限 |
| 七 | 基准与验收 | 性能基准（单步决策、单局耗时、每小时局数）→ 校准训练规模；全量验收清单；训练报告入库；创建 PR |

## 三、不可妥协约束（继承任务书）

- 训练与网页实战共用同一决策核心（同一 `src/ai` 源码编译产物）；参数升级通过 PR 更新生成式冠军参数块。
- 不修改 main；正式网页游戏行为除修复 1.3 缺陷外保持基线不变（现有测试逐条回归）。
- 隐藏信息（两类牌库顺序）在任何 AI 代码路径中不可达。
- 异常对局不伪装成正常结果，不计入胜率。
