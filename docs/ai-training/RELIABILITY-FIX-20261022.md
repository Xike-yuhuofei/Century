# AI 4.0 训练系统可靠性审查与修复报告（2026-10-22）

- 分支：`fix/ai4-training-reliability`（基于 main @ d7007ae）
- 范围：仅训练基础设施（`training/`、`.github/workflows/ai-training.yml`），不涉及神经网络、不改正式游戏 UI/规则
- 验证：training 60/60 通过（含 19 个新增回归测试）、web-v1 63/63 通过、构建产物指纹重建一致

## 一、缺陷验证（修复前证据，全部实测复现）

### P0-1 训练种子溢出与越池（evolve.mjs 旧实现 `candidateSeedBase = seedCursor++ × 1000`）

| 证据 | 数值 |
| --- | --- |
| 工作流每日全新运行（`--seed-base $(date +%Y%m%d)` = 20261021）首候选种子块 | 20,261,022,000 |
| 引擎安全上限（2^31 = 2,147,483,648） | **超出 9.4 倍** |
| 引擎实际生效种子（`engine.ts` generator 执行 `seed >>> 0`，mod 2^32 回绕） | 3,081,152,816 —— 名义值与实际序列脱钩，审计/复现断链 |
| 真实本地断点 `state.seedCursor = 20261049`（2026-10-21 实测）的下一候选块 | 20,261,050,000 → 回绕镜像 3,081,180,816 |
| 长期重叠：默认基数 100000 起步，游标走到 900,000 时训练块名义值 | **恰为 900,000,000 = 验证池起点**（≈ 88,889 代后训练种子直接落入验证池） |

- 三重危害：① 名义种子 > 2^31 触发引擎回绕，"记录的种子"无法复现"跑过的对局"；② 训练种子名义值越过 `[0, 900M)` 训练池边界，CLI 自己强制的"训练/验证隔离"不变量被派生值打破；③ 游标无界增长，训练种子回绕镜像终将与已消费验证种子的镜像重合 → 确认挑战证据被"提前训练过"的洗牌序列污染。
- 次要缺陷：无账本本地运行的验证块盐值按"天"派生——实测同日第二次无账本运行会取到与当天早前运行完全相同的验证块（941494000）。

### P0-2 长期重复挑战误晋级（每次挑战独立用 Wilson 95%）

蒙特卡洛（mulberry32，零假设 p=0.5、n=60 决定性种子，200,000 次模拟）：

| 独立重复挑战次数 | 至少一次误晋级（实测） | 理论 1−0.975^k |
| --- | --- | --- |
| 1 | 0.0257 | 0.025 |
| 30 | **0.545** | 0.532 |
| 60 | **0.791** | 0.781 |
| 120（≈4 个月日更挑战） | **0.959** | 0.952 |

结论：冠军长期在役时，每日挑战 + 每周挑战的重复检验会把 2.5% 的单次误报率累积成必然误晋级。这是"重复看数据不修正显著性"的经典多重检验问题。

### P1-1 对手池轮换塌缩（challenge.mjs 旧公式 `(seedIndex×5+seat) % pool.length`）

pool=5（工作流与 CLI 默认）时旧公式恒等于 `seat`——10 个种子 × 5 席位的分配矩阵逐行完全相同：

```
seed0..4: opp[0] opp[1] opp[2] opp[3] opp[4]   （每席位对手永不轮换）
```

危害：候选在整个训练过程中固定与"席位 s ↔ 风格 s"的绑定组合交手，风格多样性名存实亡；席位人格（策略 personality）与对手身份完全混淆，无法区分"学会打某风格"与"学会打某席位"。（pool=4 时恰好正常，掩盖了该缺陷。）

### P1-2 晋级证据完整性缺口

- 证据不含引擎版本与代码版本：引擎在证据生成后变更（如规则修复合入），旧证据仍可晋级——"旧引擎证据晋级到新引擎"无任何防线；
- 证据不携带多重检验要素（挑战序号/阈值），晋级重算固定用 95% 阈值；
- 验证种子基数只校验下界（≥ 900M），不校验上界，越池基数不被拒绝。

## 二、修复方案

### P0-1 训练种子块分配（`training/lib/seeds.mjs` + `training/optimizer/evolve.mjs` + `training/simulator/simulate.mjs`）

- **池布局**（物理隔离，全部 ≤ `ENGINE_SEED_MAX` = 2^31−1）：训练池 `[0, 900M)`（`[0, 400M)` 日常进化、`[400M, 900M)` 基准评测约定区）、验证池 `[900M, 1.06e9)`。
- **块分配**：`state.seedCursor` 改为绝对种子游标（块对齐）；每候选经 `allocateTrainingBlock()` 固定预留 1000 种子块，块互不重叠、必须完整落在训练池内，越界抛错（`训练种子池已耗尽`）而非静默越界；候选生成 rng 分流到独立的 `state.rngCursor`（逐代 +1，与游戏种子不同池不同消费者）。
- **回绕防线**：`simulateGame` 对 `seed ≥ 2^31` 直接拒绝（引擎 `seed >>> 0` 回绕的名义/实际脱钩在训练侧不可能发生；正式网页路径不受影响）。
- **旧断点自动迁移**：`migrateLegacyCursor()` 区分两种旧游标语义（小游标 = 块索引，续接在 `游标×1000` 之后；大游标 = 日期基数，对齐为池内绝对种子续用），rng 流从旧游标续接零重复，迁移事件随 `state.seedMigration` 落盘。已用真实断点（seedCursor=20261049）端到端验证：迁移到 20262000 并正确续训。
- **盐值加固**：无账本本地回退盐值从按天改为按小时派生。

### P0-2 长期多重检验控制（`training/evaluator/stats.mjs` + `challenge.mjs` + `evolve-cli.mjs` + `promote-champion.mjs`）

**机制：几何 alpha 消耗（alpha spending）**

- 账本新增 `challengeCount`（每次确认挑战 +1；旧账本按 history 条数兜底）；
- 第 k 次确认挑战的单侧显著性 α_k = ALPHA_BUDGET / 2^k（预算 5%）。Σ_{k≥1} α_k = 5%：**无论系统终身挑战多少次，家族误晋级率的严格上界恒为 5%**（各次挑战种子块互不重叠保证统计独立）；
- 阈值 z_k = Φ⁻¹(1−α_k)（Acklam 逆正态，误差 < 1.2e-9；k=1 时 z≈1.96 与旧制一致，不惩罚首次晋级）；α < 1e-15 的双精度极限处 z 饱和（对预算影响 ≤ 1e-15/次，可忽略）；
- 判定对象携带 `challengeIndex / alpha / alphaBudget / z` 随证据落盘；晋级脚本按挑战序号**独立重算**收紧后的判定，并核对自报 z 与重算 z 一致（防伪造宽松阈值）；
- 账本交叉核对：候选文件同目录若带有验证账本（工作流归档必带），`challengeIndex` 必须等于账本 `challengeCount`——防伪造小序号换宽松阈值；
- 语义保持：统计量仍是**配对得分优势率**（非先名率），真实第一名率仍由 `firstPlace` 独立披露；未达证据标准（样本不足/不确定/劣势/异常率超限）一律不晋级，行为不变。

效果：30 次重复挑战的误晋级概率从 54.5% 压到 ≤ 5%（终身），120 次从 95.9% 压到 ≤ 5%（终身）。真实优势候选不受影响——例如当前冠军证据（优势率 0.634、300 种子）在 k=2（z=2.24）下 CI 下界仍 > 0.5。

### P1-1 对手池轮换（`training/tournament/challenge.mjs`）

新公式 `(池大小−1)×(seedIndex+席位) mod 池大小`（即 −(i+s) mod L，步长与池大小恒互素）：

```
seed0: opp[0] opp[1] opp[2] opp[3] opp[4]
seed1: opp[4] opp[0] opp[1] opp[2] opp[3]   （每席位对手逐种子轮换遍历全池）
seed2: opp[3] opp[4] opp[0] opp[1] opp[2]   ...
```

- 任何池大小（1–16）下每席位对手逐种子轮换（旧缺陷 pool=5 时每席固定 1 种 → 修复后 ≥ 4 种）；
- 池 ≥ 5 时同局各对手席位对手互不重复；
- 分配只依赖 (seedIndex, seat)：双向对战同席位对手一致，配对可比性保持；
- 池首（冠军本体）经轮换以对手身份出现在席位 1–4，且永不与候选同席冲突。

### P1-2 证据完整性（`training/lib/paths.mjs` + `evolve-cli.mjs` + `promote-champion.mjs` + 工作流）

- **运行时产物指纹** `engineBundleSha256()`：对训练实际加载的运行时文件闭包（engine.js、ai.js 及其相对 import 闭包，含 data.js/ai/*）做确定性 sha256。重建构建逐位一致（实测两次构建同指纹 `826bd3c0…`）；
- `candidate.json` / `report.json` 携带 `engineBundleSha256` + `codeCommit`（git HEAD，无 git 环境为 null 并警告）；晋级时重算当前产物指纹比对，不一致（引擎在证据生成后变更过）→ **拒绝晋级，须重新确认挑战**；冠军 `provenance` 落盘指纹与代码版本，可按 commit 重建复现任意争议；
- 验证种子基数校验补上界（`[900M, 1.06e9)`）；
- challenge-cli 新增 `--challenge-index`，手动证据级挑战同样走 alpha 消耗（不带序号的结论会被晋级脚本拒绝）；
- 工作流周挑战种子基数改为 `400M + 年份×4M + 年积日×1000`（落在本轮次评测约定区，每个自然日唯一、跨年绝不重复；旧公式跨年重复同一批对局且与每日进化区相邻）。

## 四、长期统计晋级机制说明（运维视角）

1. 每次确认挑战必消耗账本一个种子块并 `challengeCount += 1`——账本是挑战次数的唯一事实来源；
2. 第 k 次挑战的晋级门槛 = 配对得分优势率的 Wilson 区间（分位数 z_k）下界 > 0.5，z_k 随 k 几何收紧：1.96 → 2.24 → 2.50 → 2.73 → 2.96 → …（10 次后 ≈ 3.9）；
3. 终身家族误晋级率 ≤ 5% 的证明：各次挑战使用互不重叠的验证种子块（账本防重保证），统计独立，P(至少一次误晋级) ≤ Σα_k = 5%（Bonferroni 型和界）；
4. 未达标准不晋级：样本不足（insufficient）/区间跨 0.5（inconclusive）/劣势（rejected）/异常率超限，均保留冠军；晋级脚本对全部证据独立重算，任何伪造/篡改/证据失效（引擎变更）都会被拒绝；
5. 平局种子不计入二项分母但披露平局率；真实第一名率始终随证据披露但不得单独触发晋级。

## 五、剩余风险清单

| 风险 | 现状/缓解 | 建议 |
| --- | --- | --- |
| 训练种子在 [0, 900M) 内跨运行理论重叠 | 同日多次全新运行（无断点）会复用同一日期块区；训练种子非晋级证据，危害有限 | 长期可给训练块也记账本；当前收益低 |
| 周挑战与日常进化同为训练池用户 | 已分约定区（[400M, 900M) vs [0, 400M)），簿记约定不强制 | 保持文档约定，勿在进化时传入 ≥ 400M 基数 |
| 无账本本地运行的验证块回退盐值 | 按小时派生，同小时多次运行仍可能撞块；`assertBlockFree` 只在有账本时生效 | 始终带 `--seed-ledger` 运行 |
| 证据"真实性"无法事后密码学证明 | promote 独立重算能识破统计篡改与引擎变更，但无法证明 seedPairs 确由真实对局产生 | 可选演进：挑验证种子子集重放对局比对 `deterministicKey` |
| z 阈值在 α < 1e-15 饱和 | 影响可忽略（≤ 1e-15/次预算）；约 55 次挑战后阈值封顶 ≈ 8.0 | 现实挑战频率下无需处理 |
| 旧版已归档候选（struct-beam-rollout.json）无新证据字段 | 仅历史归档展示，不参与新晋级（promote 对新候选强制新字段） | 无需回填 |
| 蒙特卡洛背景：Wilson 区间在极小 n 下略保守/激进波动 | 晋级门槛 minSeeds=60 决定性种子已兜底 | 维持 minSeeds 下限 |
| `codeCommit` 在非 git 环境为 null | 仅警告不阻断（溯源降级不阻塞训练） | 正式晋级一律在 CI（有 git）执行 |

## 六、完成标准对照

- **长期运行**：训练池 899,900 块 × 1000 种子，按 9 块/代可支撑约 10 万代；池耗尽显式抛错并给出处置指引，绝不静默越界；
- **正确恢复**：旧断点自动迁移（双语义覆盖 + 真实断点实测），rng/种子双游标续接零重复；
- **可靠复现**：全部分配种子 ≤ 2^31−1，名义种子即引擎生效种子；`engineBundleSha256` + `codeCommit` 把每次证据钉死到（种子 × 参数 × 代码 × 产物）；
- **不因种子缺陷误晋级**：训练/验证池物理隔离 + 验证块账本防重 + 模拟器回绕拒绝；
- **不因重复检验误晋级**：几何 alpha 消耗，终身家族误晋级率 ≤ 5%，晋级脚本独立重算强制执行。
