# Century AI 5.0 — Mac mini M4 硬件性能基准报告

> 测试日期：2026-10-21 ｜ 测试机器：Mac mini M4（10 核 CPU = 4 性能核 + 6 能效核 / 10 核 GPU / 16GB 统一内存）
> 仓库 Commit：`d7007ae1ed85012652545af392395f8b26645cb1`（main，AI 4.0 复审整改 P0/P1 #12）
> 原始数据：`experiments/ai5-m4-benchmark/results/`（env_audit.json / mlp_benchmark.json / selfplay_benchmark.json）
> 纪律：本报告仅为环境测试与硬件评估，未修改 AI 4.0 正式算法及任何 Agent A 负责目录。

---

## 1. 核心结论（先读这里）

1. **M4 16GB 完全可以承担 Century AI 5.0 的小型神经网络 + 自对战 RL 训练。** 推荐网络规模为 **2–4 个隐藏层 × 256 单元（约 7 万–20 万参数，上限 4×512 ≈ 100 万参数）的 MLP**，配合 **PPO 自对战**架构。
2. **训练不是瓶颈，模拟才是。** 4×256 网络 MPS batch=512 完整训练步仅 1.30ms（约 39.3 万样本/秒），而自对战模拟在 8 进程下也只有约 8217 局/小时（约 152 万决策/小时）。GPU 大部分时间空闲，应把资源投在 CPU 模拟侧。
3. **多进程扩展在 4 worker 时效率 80.3%，8 worker 时跌至 54.5%**（E 核拖慢 + 内存带宽争用）。推荐 **4 个模拟进程**作为默认配置。
4. **batch size 推荐 512（MPS）**；隐藏层 ≤128 的小网络直接用 CPU 更快（MPS 内核启动开销 ~0.14–0.25ms/算子链，小网络不划算）。
5. **无需升级硬件**即可启动 AI 5.0；仅当计划使用 >200 万参数模型、注意力结构或 >2GB 经验回放缓冲时常驻训练时，才建议 32GB 内存机型。

## 3. 神经网络性能基准：CPU vs MPS（任务二实测）

### 测试口径

- 网络：输入 256 维状态向量、输出 128 维动作 logits 的 MLP（与 Century 离散动作策略网络量级一致）。
- 三种规模：2 隐层×128、3 隐层×256、4 隐层×256。
- 完整训练步 = 前向 + MSE 反向 + AdamW 步。
- 协议：预热 10 迭代 → 每配置重复测量 3 轮 × 30 迭代，MPS 每窗口末尾 `torch.mps.synchronize()`；另附逐相位分解（含同步开销，仅作占比参考）。

### 完整训练步耗时（ms，均值±标准差，越小越好）

| 架构 | Batch | CPU step | MPS step | CPU 样本/秒 | MPS 样本/秒 | 胜者 |
|---|---|---|---|---|---|---|
| 2×128 | 64 | **0.295**±0.010 | 0.783±0.010 | **217,195** | 81,743 | CPU |
| 2×128 | 128 | **0.358**±0.012 | 0.740±0.007 | **357,269** | 172,978 | CPU |
| 2×128 | 256 | **0.444**±0.010 | 0.768±0.012 | **576,280** | 333,550 | CPU |
| 2×128 | 512 | **0.641**±0.011 | 0.798±0.045 | **798,298** | 641,776 | CPU |
| 3×256 | 64 | **0.752**±0.014 | 1.022±0.002 | **85,103** | 62,613 | CPU |
| 3×256 | 128 | **0.868**±0.012 | 1.021±0.014 | **147,507** | 125,345 | CPU |
| 3×256 | 256 | 1.145±0.019 | **1.005**±0.011 | 223,521 | **254,780** | MPS |
| 3×256 | 512 | 1.444±0.013 | **1.053**±0.021 | 354,623 | **486,241** | MPS |
| 4×256 | 64 | **0.973**±0.009 | 1.389±0.098 | **65,745** | 46,079 | CPU |
| 4×256 | 128 | 1.194±0.131 | **1.258**±0.044 | 107,192 | **101,745** | ≈持平 |
| 4×256 | 256 | 1.495±0.047 | **1.289**±0.036 | 171,184 | **198,653** | MPS |
| 4×256 | 512 | 1.863±0.027 | **1.303**±0.016 | 274,863 | **393,031** | MPS（1.43×） |

### 前向推理耗时（ms）

| 架构 | Batch 64 | Batch 128 | Batch 256 | Batch 512 |
|---|---|---|---|---|
| 2×128 | CPU **0.031** / MPS 0.138 | CPU **0.043** / MPS 0.158 | CPU **0.059** / MPS 0.166 | CPU **0.152** / MPS 0.195 |
| 3×256 | CPU **0.069** / MPS 0.206 | CPU **0.099** / MPS 0.238 | CPU **0.248** / MPS 0.300 | CPU **0.337** / MPS 0.344 |
| 4×256 | CPU **0.092** / MPS 0.252 | CPU **0.153** / MPS 0.291 | CPU **0.309** / MPS 0.383 | CPU **0.430** / MPS 0.437 |

### 关键发现

1. **MPS 存在固定启动开销**：逐相位数据显示即使 batch=64，MPS 单算子链也有 ~0.14–0.25ms 底价（fwd/bwd/opt 三相位各约 0.4–0.9ms，其中含同步开销）。网络越小、batch 越小，CPU 越占优。
2. **交叉点在「3 层×256 + batch≥256」**：此后 MPS 全面反超，4×256/b512 时 MPS 吞吐是 CPU 的 1.43 倍。
3. **反向 + 优化器步合计约占总步时的 65%**（窗口口径：step − fwd，如 4×256/b512 为 0.87ms/1.30ms），优化器步（AdamW on MPS）实测约 0.6–0.9ms，占比可观——若追求极致可测试 fused AdamW 或 SGD-momentum。
4. **内存开销极小**：MPS driver 内存峰值仅 ~28MB（4×256/b512），宿主 Python 进程峰值 RSS 约 456MB（含 PyTorch 运行时）。**稳定性无问题**（所有配置标准差 <10%，无 OOM、无 nan）。

## 4. Century 自对战并行吞吐量（任务三实测）

> 引擎：`web-v1/dist/js` 正式编译产物 + AI 4.0 冠军参数（beam-rollout 结构），训练模拟器 `training/simulator/simulate.mjs` 原样复用，未做任何算法修改。
> Commit：`d7007ae1ed85012652545af392395f8b26645cb1`（**Agent A 修复后请以此基线重测对比**）
> 种子段：5,000,000 起（独立段，避开确认挑战 900M 账本）；每 worker 预热 1 局 + 计量 30 局；CPU/RSS 为 ps 每 500ms 采样均值。

| Worker 数 | 总对局 | 局/小时 | 单局均时 | 平均步数 | CPU 核当量 | RSS 均值 | 扩展效率 | 异常局 |
|---|---|---|---|---|---|---|---|---|
| 1 | 30 | 1,885 | 1858ms | 180.4 | 1.00 | 126MB | 100%（基准） | 0 |
| 2 | 60 | 3,546 | 1971ms | 185.8 | 1.99 | 254MB | **94.1%** | 0 |
| 4 | 120 | 6,057 | 2232ms | 184.1 | 3.85 | 462MB | **80.3%** | 0 |
| 8 | 240 | **8,217** | 3249ms | 185.3 | 7.29 | 894MB | 54.5% | 0 |

### 关键发现

1. **450 局全部正常完成，零异常**——模拟器在该机器上稳定可靠。
2. **2 worker 几乎完美扩展（94.1%）**；4 worker 时单局变慢 20%（1858→2232ms）但总吞吐仍 +221%，可接受；8 worker 时单局变慢 75%（E 核承载 + 内存带宽争用），扩展效率跌破 55%。
3. 8 worker 只用了 7.29 核当量——并非调度不满，而是 6 个 E 核本身性能约为 P 核的 1/2~1/3，拉低了平均。
4. 内存开销可预测：**每 worker 约 115–130MB**，8 worker 峰值 <1GB，对 16GB 无压力。
5. 换算决策吞吐：8 worker ≈ 8217 局 × 185 步 ≈ **152 万决策/小时**（与既有 perf 报告单核 1760 局/小时、11.9ms/决策口径一致，本次数据可交叉验证）。

## 6. AI 5.0 推荐训练配置（任务四）

### 6.1 适合 M4 16GB 的神经网络规模

- **推荐起点**：2 隐层 × 256（约 16.5 万参数，输入 256 / 输出 128 口径）；**主力规模**：3–4 隐层 × 256（约 23 万–30 万参数）。
- **上限**：4 隐层 × 512 ≈ 100 万参数（按实测线性外推，MPS b512 训练步约 5ms，仍可行）。
- **不建议**：>200 万参数、注意力/序列结构、大型卷积栈——非算力不够，而是会被 CPU 模拟瓶颈与内存压力放大为无效投入。
- 状态编码 256 维、动作 128 维的假设已验证；若输入扩展到 512 维，结论不变（网络 FLOPs 增幅 <1 倍）。

### 6.2 建议的并行环境数量

- **默认 4 个模拟进程**（80.3% 效率，6057 局/小时，机器仍有余量响应其他任务）。
- 无人值守过夜训练可提到 **6 进程**（介于 80% 与 54.5% 之间，预计 ~7000 局/小时）。
- **不要超过 8**；同时保留至少 1 个 P 核给 Python 训练编排进程。

### 6.3 CPU 模拟与 GPU 训练的资源分配

推荐「**模拟为主、GPU 即插即用**」的分工：

- **CPU（4–6 核）**：Node 模拟进程持续生成对局（JSONL 逐局落盘或流式输出）。
- **GPU（MPS）**：Python 训练进程消费转移样本做 PPO 更新。按 4 worker 产量（约 112 万决策/小时）估算，一个 10 万样本的 PPO 更新周期（4 epoch × 512 batch ≈ 780 步 × 1.3ms）仅需约 1 秒，**GPU 占空比 <0.1%**，与模拟并发互不干扰。
- 无需做 CPU/GPU 时间片切分——两者天然异步。

### 6.4 推荐的 Batch Size

- **512（MPS）**：3–4 层×256 网络的最佳吞吐点（39–49 万样本/秒）。
- 若经验缓冲偏小或做小步快跑实验：256。
- 隐藏层 ≤128 的轻量网络：直接用 CPU + batch 512（79.8 万样本/秒）。

### 6.5 是否适合 PPO 自对战强化学习

**适合，且这是正确的架构方向：**

- 实测数据链路完整：4 worker × 1 小时 ≈ 112 万转移样本；PPO 在 20 万参数 MLP 上的更新成本可忽略，采样才是稀缺资源——这正是 PPO（样本效率导向、on-policy 小批量多次复用）优于纯策略梯度场景的特征。
- 自对战稳定性依赖对手池（已有 AI 4.0 对手池基础设施 `training/lib/opponents.mjs` 可复用）。
- MPS 数值一致性已验证（14/14 算子 allclose），训练-推理设备分离（JS CPU 推理 + PyTorch MPS 训练）不存在算子缺口。
- 唯一注意点：JS 模拟器与 Python 训练器之间的状态编码必须同源（建议沿用 AI 4.0 AIObservation 公平信息约定，编码层单测对齐）。

### 6.6 训练瓶颈与优化优先级

1. **P0 — JS 决策引擎单步耗时（~12ms/决策）**：GPU 严重闲置，任何模拟侧提速都直接等比提升训练迭代速度。优先级高于一切 GPU 侧优化（本任务不改动，留给 Agent A 修复后重测）。
2. **P1 — worker 数量与进程模型**：4→6 进程；可测试「1 进程多 worker_threads」降低 fork 开销。
3. **P2 — 模拟↔训练数据管道**：避免每局 JSON 全量落盘再读取；用流式 JSONL + 批量读取，或本机 Unix socket。
4. **P3 — MPS 小算子开销**：批内合并、fused 优化器、`torch.compile`（MPS 后端）可再压缩训练步时间，但收益上限低（GPU 本就空闲）。
5. **P4 — 系统内存纪律**：长训时段关闭高内存应用，训练进程组 <6GB，监控 swap。

### 6.7 是否需要升级硬件

**现阶段不需要。** 判断依据：

- 训练侧实测峰值内存 <1GB（含运行时），GPU 占空比 <0.1%，10 核 CPU 有 2–3 核余量。
- **触发升级的明确条件**（满足其一再考虑）：
  - 模型 >200 万参数或引入序列/注意力结构；
  - 经验回放/对手池常驻内存 >2GB 且需与日常应用共存；
  - 需要全天候无人值守且同时使用这台机器办公；
  - 届时优先考虑 **32GB 统一内存**机型（Apple Silicon 内存不可更换，一步到位），算力（M4→M 系列 Pro/Max）优先级低于内存。

- **统计口径沿用**：训练实验继续记录随机种子、参数、代码版本（与 AI 4.0 演进链路同一纪律）；本基准种子段 5,000,000+ 与挑战账本 900M 隔离。

- **禁止事项回顾**：未改动 `training/optimizer/`、`training/evaluator/`、`training/tournament/`、正式网页代码；未创建任何 PR。
